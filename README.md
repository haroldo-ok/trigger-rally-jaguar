# Trigger Rally — Atari Jaguar native port

**Experimental drivable racing build. Full original-game conversion is still incomplete.**

The accelerator now produces visible, near-real-time vehicle motion rather than the previous multi-second game frames. This is an actual Jaguar cartridge: the **68000 boots the cartridge**, the **DSP runs the game, vehicle simulation and audio**, and **42Bastian’s `jag_3d_engine` runs on the GPU**. No host-side game simulation, substituted video or emulator overclock is used.

Both requested upstream projects remain the targets:

- [Code Artemis / TriggerRally](https://github.com/CodeArtemis/TriggerRally), revision `079ac53216b74598b652ce3bf11478beb5c6832b`.
- [42Bastian / jag_3d_engine](https://github.com/42Bastian/jag_3d_engine), revision `f8bc66bf27346f73ec91719b62932b9ceef37d50`.

## What changed for driving

The old 68000/software-float implementation advanced about **0.7 completed game frames/sec** in its recorded mixed-state regression. A frontend saying “60 FPS” did not mean the car was updating at 60 FPS.

The new implementation:

- Moves the native game and physics onto the **real Jaguar DSP**, alongside its interrupt-driven PCM mixer.
- Supplies local-DSP binary32 arithmetic, including assembly hot paths, rather than interpreting physics on the host.
- Overlaps DSP simulation of the next pose with GPU rendering of an immutable submitted scene.
- Caches immutable scenery transforms and collision spheres; all authored instances remain in collision.
- Composes render-only wheel steering/spin with Q15 matrices in the original quaternion order. Physics keeps its full body orientation and forces.
- Uses a **50 Hz native fixed-step solver**, rather than the browser’s 150 Hz integration cadence. The ported drivetrain, suspension, tyre/chassis/scenery contacts, recovery and wing-force systems remain; this is a numerical/hardware adaptation, not a claim of identical browser physics.
- Keeps BIOS-on and BIOS-off boot, and adds a genuine `$802000` compatibility jump to the `$83F000` ROM-copy bootstrap for frontends hard-wired to that address.

Physical Jaguar hardware and all possible driving paths have not been validated. ## Build from sources

Linux with **Python 3.12 or newer** is the tested build host. Extract the source ZIP with a tool that preserves its stored timestamps, such as `unzip`, then enter its project directory:

```sh
unzip trigger-rally-jaguar-sources.zip
cd trigger-rally-jaguar
```

Preserving timestamps prevents Make from mistaking extraction order for an edit to the asset converter and unnecessarily regenerating the included asset bank. Install the native and cross-compilation tools:

```sh
sudo apt-get update
sudo apt-get install build-essential gcc-m68k-linux-gnu binutils-m68k-linux-gnu python3-venv
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
make -j4 all
```

Output: **`releases/trigger-rally-jaguar.j64`**, a 4 MiB cartridge.

The source package contains the converted asset bank, font and signed-loader input, plus their conversion/bootstrap sources. It does **not** require a network download or original asset regeneration for a normal build. The assembler, JRISC C compiler, JRISC assembler and linker are built from pinned vendored source archives into `.cache/`.

**Tool licensing:** vbcc is source-available with non-commercial-use restrictions; its original archives are retained unchanged and the project’s compiler fixes are a separate patch. Commercial tool use needs the author’s permission under its terms. No vbcc C runtime is linked into this game. Read `vendor/jrisc/UPSTREAM-README.txt`, the legal section inside its source archive and [LICENSES.md](LICENSES.md).

Do not replace the locally built 68000 arithmetic test runtime with the distribution’s default `-lgcc`; some objects require instructions absent from Jaguar’s 68000.

For independent asset regeneration, install `ffmpeg`, obtain the pinned original repository with `make fetch-upstream`, then use `make regenerate-assets`. See [BUILDING.md](docs/BUILDING.md). Regeneration is separate from compiling the included converted build data.

## Run in desktop Virtual Jaguar

```sh
sudo apt-get install virtualjaguar
python3 tools/run_virtual_jaguar.py --bios off
```

The launcher uses the actual ROM by absolute path and enables GPU/DSP. Both BIOS paths are supported. The signed loader remains unchanged; the ROM-copy bootstrap and compatibility entry are real 68000 code, not a forced BIOS preference in the test.

### Controls

**Virtual Jaguar 2.1.3 default keyboard mapping:**

| Keyboard | Jaguar controller |
|---|---|
| **L / K / J** | **A / B / C** |
| **S / Z / X / C** | Up / left / down / right |
| **P / O** | Pause / Option |
| Number keys | Jaguar keypad |

**Hold L to start and accelerate. J is the handbrake, not the accelerator.** Wait for the approximately three-second READY countdown. Arrow keys are not this emulator version’s default d-pad; custom profiles may differ.

| Screen | Controller actions |
|---|---|
| Menu | Left/right: course; up/down: car; A: race; keypad 1: last RAM replay |
| Race | A/up: throttle; B/down: brake/reverse; C: handbrake; left/right: steer |
| Race/replay | Pause: pause/resume; Option: menu |
| Race | Keypad 3: restart; 0: recover; 2: camera |
| Finish | A: race again; 1: replay; Option: menu |

Use steering to follow the course: holding the accelerator forever on a curved track will eventually hit scenery. Recovery is available on keypad 0. Replays and best times are **RAM-only**.

### What the gates require

- **Driving suite:** six NTSC track/car combinations and both cars on Base under PAL. It checks real-time countdown, accelerator displacement/speed, live changing 3D video, completed game FPS, race-clock rate, braking, actual heading change and pause. Base/car0 must genuinely finish through ordered checkpoints in NTSC and PAL.
- **Specific movement controls:** a cartridge with zero engine power must fail the displacement check; a native delayed-racing cartridge must fail timing/performance checks. A live menu/GPU counter alone cannot pass.
- **Safety matrix:** 13 BIOS/video/blitter/frontend configurations, actual desktop gameplay, and five real entry/black/frozen-scene cartridge controls with specific watchdog errors. Post-boot controls include a healthy observable interval first.
- **Full core interactions:** both NTSC BIOS paths, real controller scans, physics, checkpoint progress, replay, restart and reset/soak.
- **Arithmetic/render units:** 10,240 DSP arithmetic operations plus edge values, fixed-point matrix comparisons and a separate 4,096-operation real-68000 test. Unit cartridges are not used as gameplay evidence or distributed as the game.
- **Preferred-source rebuild:** clean native builds and an extracted-source build must reproduce the tested ROM.

The core tests supply only real controller inputs and read native/video/audio diagnostics. The desktop tests launch the actual application with fresh settings, send real keyboard/mouse events, capture its window and decode the cartridge’s font. No emulator RAM/register writes, mock car physics or fixture-video substitution are used. Static PNG fixtures are only font-decoder unit-test inputs.

The driving gate’s controlled-run floor is **12 completed FPS for NTSC / 10 for PAL**, with a near-real-time race clock. The older 15/20-second progress watchdogs detect deadlocks, **not playability**. Missing dependencies fail rather than silently skip. No finite E2E can prove “never freezes.”

## Source and release packaging

Create the dedicated source distribution from the project root:

```sh
python3 tools/make_source_archive.py
# releases/trigger-rally-jaguar-sources.zip
(cd releases && sha256sum -c SOURCES.sha256)
```

The ZIP extracts into one **`trigger-rally-jaguar/`** directory:

| Included path | Contents |
|---|---|
| `src/` | 68000 bootstrap/host, actual DSP game/physics/audio, render-only matrix code and adapted 42Bastian GPU engine |
| `assets/` | Required converted asset bank, IDs, manifest and memory-map data |
| `tools/` | Source-build, asset-conversion, archive, release-verification and compiler-patch tools |
| `tests/` | Actual-ROM core/desktop driving and safety regressions, native arithmetic kernels and authentic font-decoder unit fixtures |
| `vendor/` | Unmodified JRISC build-tool source archives, lyxass/BJL/runtime sources and filtered Virtual Jaguar build sources |
| `docs/`, `licenses/`, `.github/` | Build/test/status documentation, rights notices and CI workflow |
| `SOURCE_MANIFEST.json` | Byte counts and SHA-256 hashes for every packaged source/input entry |

This is a **source-and-required-build-data package**, not exclusively text: the converted asset bank, bitmap font and pre-signed loader input are retained with their conversion/bootstrap sources. The game ROM, emulator executable, compiled assembler, object/ELF files, generated GPU/DSP program binaries, caches and historical test reports are excluded. A clean build reconstructs the native code.

The emulator snapshot drops optional website artwork/precompiled test images while retaining source/build/license file contents. Its preferred-source build was checked by the independent extracted-delivery test. **Run `make test-core` before E2E tests**, because the source ZIP has no prebuilt core `.so`. Licenses and original content restrictions still apply.

A tested ROM/evidence release is a different operation:

```sh
make test
python3 tools/check_reproducibility.py
(cd releases && sha256sum trigger-rally-jaguar.j64 > ROM.sha256)
make release
python3 tools/check_packaged_build.py
make release  # adds the extracted preferred-source proof
```

The release gate refuses stale/failed/incomplete evidence or reports for a different ROM/core/source set. A source-only extraction starts without release reports; regenerate them instead of copying old passes. Enable the included CI workflow as a required repository check if hosted merge blocking is wanted.

## Remaining full-port requirements

Drivable racing is **not full TriggerRally feature parity**. The native editor, persistent storage, account/profile/browser/sharing/network workflows, complete replay/ghost state, full audio/effect/particle behavior and several rendering/content-fidelity details remain incomplete. Terrain is a cropped, quantized native window rather than the full original landscape; Icarus articulation and hardware/flight edge cases remain unverified or incomplete.

These are remaining requirements, **not an agreed scope reduction**. No placeholder menus are presented as working features. See [PORT_STATUS.md](docs/PORT_STATUS.md), [PLAYABILITY.md](docs/PLAYABILITY.md), [ENGINE_INTEGRATION.md](docs/ENGINE_INTEGRATION.md) and [TESTING.md](docs/TESTING.md).
